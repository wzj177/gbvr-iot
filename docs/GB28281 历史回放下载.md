## ✅ 一、你的 POST API 设计（接收请求）

### 接口定义
```http
POST /api/v1/gb28181/download
Content-Type: application/json
```

### 请求体（JSON）
```json
{
  "device_id": "34020000001320456628",     // 设备主 ID（用于路由）
  "channel_id": "34020000001310000001",    // 通道 ID（用于查询）
  "start_time": "2026-01-14T08:06:21",     // ISO8601
  "end_time": "2026-01-14T08:06:34",
  "speed": 2,                              // 可选：1, 2, 4（倍速）
  "save_path": "/data/downloads/"          // 可选：保存路径

```

> 📌 **注意**：
> - `channel_id` 必须是 **20 位通道编码**（不是数字 1/2）；
> - 时间必须是 **ISO8601**，后端转为 Unix 时间戳。

## ✅ 二、国标服务器需下发的 SIP 指令（核心！）

### 步骤：向设备发送 `INVITE` 请求

#### 1. **SIP 消息头**
```http
INVITE sip:34020000001310000001@<设备IP>:<设备SIP端口> SIP/2.0
Via: SIP/2.0/UDP <你的SIP服务器IP>:5060;branch=z9hG4bKxxxxx
From: <sip:34020000002000000001@<你的SIP服务器IP>>;tag=yyyyy
To: <sip:34020000001310000001@<设备IP>>
Call-ID: unique-call-id-for-this-download
CSeq: 1 INVITE
Subject: 34020000001310000001:1234567890:34020000002000000001:0987654321
Contact: <sip:34020000002000000001@<你的SIP服务器IP>:5060>
Content-Type: application/sdp
Content-Length: [SDP长度]
Max-Forwards: 70
User-Agent: SafetyWay/1.0
```

> 📝 **`Subject` 字段格式（标准要求）**：  
> `视频源ID:发送方SSRC:接收者ID:接收端SSRC`  
> 例如：`34020000001310000001:1234567890:34020000002000000001:0987654321`

---

#### 2. **SDP 消息体（关键！必须含 `s=Download`）**
```sdp
v=0
o=34020000002000000001 0 0 IN IP4 <你的媒体网关IP>
s=Download
u=34020000001310000001,Download
t=1705223181 1705223194
a=downloadspeed:2
c=IN IP4 <你的媒体网关IP>
m=video <RTP端口> RTP/AVP 96
a=rtpmap:96 H264/90000
a=recvonly
```

> 🔑 **SDP 字段说明**：
> | 字段 | 值 | 说明 |
> |------|-----|------|
> | `s` | `Download` | **必须！标识下载模式** |
> | `u` | `<通道ID>,Download` | 通道 ID + 下载类型 |
> | `t` | `开始时间 结束时间` | **Unix 时间戳（秒）** |
> | `a=downloadspeed` | `1`/`2`/`4` | 倍速参数（可选） |
> | `m=video` | `端口 RTP/AVP 96` | RTP 端口由你的媒体网关分配 |
> | `a=recvonly` | — | 表示平台只收流 |

---

## ✅ 三、后续处理流程

### 1. **设备回复 `200 OK`**
- 你的 SIP 服务器收到后，向媒体网关发 `ACK`；
- 媒体网关开始接收 RTP 流。

### 2. **启动下载器（Downloader）**
- 你的服务监听媒体网关的 RTP 端口；
- 用 **FFmpeg** 将 RTP 流保存为 MP4：
  ```bash
  ffmpeg -i rtp://<网关IP>:<端口> -c copy -f mp4 /path/to/save.mp4
  ```

### 3. **结束通知（理想情况）**
- 设备播完后发 `MESSAGE` 通知“下载完成”；
- 你的 SIP 服务器转发给业务系统。

### 4. **超时兜底（现实情况）**
- 若 30 秒无 RTP 包 → 强制结束 FFmpeg；
- 发送 `BYE` 释放会话。

---

## ⚠️ 四、关键注意事项

### 1. **时间戳转换**
- 前端传 `2026-01-14T08:06:21` → 后端转为 Unix 时间戳：
  ```php
  $start_ts = strtotime("2026-01-14T08:06:21"); // PHP
  // 或
  $start_ts = (new DateTime("2026-01-14T08:06:21"))->getTimestamp(); // 更安全
  ```

### 2. **媒体网关角色**
- 你的 SIP 服务器 **不直接收 RTP**；
- 必须通过 **SRS/ZLMediaKit** 等网关中转。

### 3. **设备兼容性**
- **测试设备是否支持 `s=Download`**：
    - 用 Wireshark 抓包，看设备是否回复 `200 OK`；
    - 若返回 `488 Not Acceptable` → 设备不支持，需降级到 HTTP 下载。

---

## 📌 五、总结：你必须做的

| 组件 | 动作 |
|------|------|
| **API 层** | 提供 `POST /api/v1/gb28181/download` 接收请求 |
| **SIP 服务** | 发送 `INVITE` + SDP（`s=Download` + `a=downloadspeed`） |
| **媒体网关** | 接收 RTP 流（如 SRS/ZLM） |
| **Downloader** | 用 FFmpeg 保存 RTP 为 MP4 |
| **清理机制** | 超时后发 `BYE` 释放资源 |

> 💡 **最后建议**：  
> 先用 **海康/大华设备测试 `INVITE s=Download` 是否被接受**。  
> 如果设备返回 `488`，则说明 **该设备不支持国标下载**，你应提供 **HTTP 下载备用方案**。
