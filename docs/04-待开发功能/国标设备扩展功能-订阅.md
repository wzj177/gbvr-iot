## ✅ 一、是否需要扩展相关能力？

> **是的，强烈建议扩展。**

虽然基础点播（INVITE/ACK/BYE）可以满足视频拉流，但一个**完整的 GB28181 平台必须支持订阅机制**，原因如下：

| 场景 | 是否需要订阅？ | 说明 |
|------|----------------|------|
| 自动获取设备通道列表更新 | ✅ 必须 | 设备增删通道时平台应自动感知 |
| 接收报警事件（如门磁触发） | ✅ 必须 | 报警通道需通过 `SUBSCRIBE` + `NOTIFY` 上报 |
| 设备状态变化（在线/离线） | ✅ 建议 | 避免轮询 Catalog，提升效率 |
| PTZ 控制反馈、位置上报 | ✅ 可选 | 用于智能联动 |

你截图中的 “**订阅项目**” → 目录、报警、位置、PTZ(2022) 正是这些订阅项！

## ✅ 二、国标中如何发起订阅和接收？

### 📌 核心协议：SIP `SUBSCRIBE` + `NOTIFY`

GB/T 28181 使用 SIP 的 **事件通知框架（Event Notification Framework）** 实现订阅：

- **平台 → 设备**：发送 `SUBSCRIBE` 请求，指定要订阅的事件类型
- **设备 → 平台**：响应 `200 OK`，并周期性或事件触发时发送 `NOTIFY`
- **平台 → 设备**：可发送 `UNSUBSCRIBE` 取消订阅

---

### 🧩 订阅事件类型（Event）

在 GB28181 中，事件类型通过 `Event` 头字段定义，常见值：

| Event 类型 | 含义 | 对应 XML CmdType |
|------------|------|------------------|
| `Catalog` | 设备目录变更（通道增删改） | `CmdType=DeviceList` |
| `Alarm`   | 报警事件上报 | `CmdType=Alarm` |
| `MobilePosition` | 移动设备位置上报 | `CmdType=MobilePosition` |
| `DeviceStatus` | 设备状态变化（ON/OFF） | `CmdType=DeviceStatus` |
| `PTZControl` | PTZ 控制反馈（可选） | `CmdType=PTZControl` |

> 🔍 注意：`PTZ(2022)` 是新版本对 PTZ 控制事件的扩展，非标准核心事件。

---

### 📥 订阅请求示例（SIP SUBSCRIBE）

```http
SUBSCRIBE sip:34020000001320948622@3402000000 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.100:5060;branch=z9hG4bK123456
Max-Forwards: 70
From: <sip:34020000001310000001@3402000000>;tag=12345
To: <sip:34020000001320948622@3402000000>
Call-ID: abcdefghijklmnopqrstuvwxyz@192.168.1.100
CSeq: 1 SUBSCRIBE
Contact: <sip:34020000001310000001@192.168.1.100:5060>
Event: Catalog
Expires: 3600
Content-Length: 0
```

> ⚠️ 关键字段：
> - `Event: Catalog` → 订阅设备目录变更
> - `Expires: 3600` → 订阅有效期（秒）
> - 无消息体（Content-Length: 0），因为只是订阅控制

### 📤 设备上报示例（NOTIFY）

当设备通道有变化时，主动发送 `NOTIFY`：

```xml
<?xml version="1.0"?>
<Notify>
  <CmdType>Catalog</CmdType>
  <SN>12345</SN>
  <DeviceID>34020000001320948622</DeviceID>
  <SumNum>1</SumNum>
  <DeviceList>
    <Item>
      <DeviceID>34020000001310000001</DeviceID>
      <Name>new_channel</Name>
      <Status>ON</Status>
      ...
    </Item>
  </DeviceList>
</Notify>
```

> 💡 平台收到后，应更新本地设备树，无需再手动调用 `query_catalog`。

## ✅ 三、相关配置是在发送指令组合的吗？

### ✔️ 是的！订阅行为由**平台侧配置决定**，并在建立连接时或按需发送 `SUBSCRIBE` 指令。

你的 UI 界面中 “**订阅项目**” 就是这个配置入口：

| 订阅项 | 对应操作 |
|--------|----------|
| ✅ 目录 | 发送 `SUBSCRIBE Event: Catalog` |
| ✅ 报警 | 发送 `SUBSCRIBE Event: Alarm` |
| ✅ 位置 | 发送 `SUBSCRIBE Event: MobilePosition` |
| ✅ PTZ(2022) | 发送 `SUBSCRIBE Event: PTZControl`（可选） |

> 📌 在设备注册成功后（或用户勾选订阅项后），平台应**立即发送对应的 `SUBSCRIBE` 请求**。

## ✅ 四、你的 PHP/eXosip 扩展如何实现？

### 1. 发起订阅（使用 eXosip）

```c
// C 扩展伪代码（eXosip API）
int subscribe_catalog(eXosip_t *ctx, const char *device_id, int expires)
{
    osip_message_t *subscribe;
    int tid;

    // 创建 SUBSCRIBE 消息
    eXosip_subscribe_build_initial_request(ctx, &subscribe, 
        device_id, "Catalog", expires);

    if (subscribe == NULL) return -1;

    // 发送
    tid = eXosip_subscribe_send_request(ctx, subscribe);
    if (tid <= 0) {
        osip_message_free(subscribe);
        return -1;
    }

    return tid;
}
```

> ✅ 在 PHP 层可封装为：
> ```php
> $platform->subscribe($deviceId, 'Catalog', 3600);
> ```

### 2. 接收 NOTIFY

```c
// eXosip 事件循环中处理 NOTIFICATION
case EXOSIP_NOTIFICATION_REQUEST:
    if (is_event_type(event->request, "Catalog")) {
        parse_catalog_notify(event->request);
    } else if (is_event_type(event->request, "Alarm")) {
        handle_alarm_event(event->request);
    }
    break;
```

## ✅ 五、工程建议

1. **订阅应在设备上线后自动发起**（根据平台配置）
2. **订阅有效期到期前自动续订**（发送新的 `SUBSCRIBE`）
3. **存储订阅关系**（设备 ID + Event 类型 + Expiry Time）
4. **UI 配置同步到设备档案**（如你截图中的“订阅项目”）
5. **错误处理**：设备不支持某事件类型 → 返回 `489 Bad Event`
