升级到GB/T 28181-2022的关键步骤


2022版新增设备软件升级、图像抓拍信令流程，并扩展了H.265、AAC等编码支持‌
需重点实现以下功能：
- 通过SIP MESSAGE消息发送升级命令（含Manufacturer/Model/Firmware字段）‌
- 支持TCP媒体流传输的重连机制（重连间隔≥1秒，次数≥3次）‌

---
‌具体实施步骤‌

- 设备信息适配‌：在设备注册时返回<Manufacturer>、<Model>、<Firmware>字段，确保升级包匹配‌

- ‌信令流程调整‌：升级命令需包含SessionID，并在结果通知中保持一致性‌;设备升级前需注销，安装完成后重新注册‌

‌- 媒体传输优化‌：实现TCP流媒体传输的RTP时间戳同步‌;调用SetGBTCPConnectTimeout等接口配置重连参数‌

---
‌
测试与验证‌

- 模拟升级流程，验证命令SN值、SessionID的匹配性
- 测试TCP媒体流在弱网环境下的重连稳定性

# 信令

## 设备软件升级信令流程

### 升级请求命令‌

```xml
<?xml version="1.0"?>
<Control>
  <CmdType>DeviceControl</CmdType>
  <SN>80267728</SN>
  <DeviceID>31020000011310000073</DeviceID>
  <DeviceUpgrade>
    <Manufacturer>test</Manufacturer>
    <Firmware>V3.7.191-b20241227</Firmware>
  </DeviceUpgrade>
</Control>

```

### 设备信息查询响应‌

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
  <CmdType>DeviceInfo</CmdType>
  <SN>123456</SN>
  <DeviceID>31020000011310000073</DeviceID>
  <Manufacturer>xxxxxxxx</Manufacturer>
  <Model>yyyyyyyyy</Model>
  <Firmware>zzzzzzzz</Firmware>
</Response>

```

## 图像抓拍信令流程

### 图像抓拍配置命令‌
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Control>
  <CmdType>DeviceControl</CmdType>
  <SN>80267729</SN>
  <DeviceID>31020000011310000073</DeviceID>
  <Snapshot>
    <SessionID>A1FBCA20ACF640D8BA317E4DC4620802677281FD</SessionID>
  <ImageFormat>JPEG</ImageFormat>
    </Snapshot>
</Control>

```

### 抓拍图像传输完成通知‌

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Notify>
  <CmdType>MediaStatus</CmdType>
  <SN>80267730</SN>
  <DeviceID>31020000011310000073</DeviceID>
  <NotifyType>SnapshotComplete</NotifyType>
  <SessionID>A1FBCA20ACF640D8BA317E4DC4620802677281FD</SessionID>
  <FileURL>http://192.168.1.73/snapshot/image.jpg</FileURL>
</Notify>

```

---
关键实现要点

‌- SessionID一致性‌：升级和抓拍过程中的SessionID必须在请求和结果通知中保持一致
‌- SN值匹配‌：应答命令中的SN值要与请求命令中的SN值一致
‌- 设备信息字段‌：升级前需提供Manufacturer、Model、Firmware字段确保版本匹配

建议在实际部署前，先使用这些XML模板进行协议兼容性测试，确保信令交互符合GB28181-2022规范要求。
