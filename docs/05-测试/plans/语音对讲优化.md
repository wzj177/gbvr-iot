# 📌 Voice Talk（GB28181 语音对讲）优化 Plan

**目标：稳定、可恢复、无误杀、支持并发**

---

## 🎯 总体目标（CC 要始终记住）

1. **任何会话只能被结束一次**
2. **超时只改变状态，不直接做副作用**
3. **状态机是唯一事实源**
4. **所有资源释放必须幂等**
5. **事件驱动 > 定时器驱动**

---

## 一、数据库层优化（第一优先级）

### 1.1 gv_voice_sessions 表结构调整,建立migration

**新增字段**

```sql
ALTER TABLE voice_session
ADD COLUMN expires_at DATETIME NULL COMMENT '会话超时时刻',
ADD COLUMN version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本',
ADD COLUMN ended_reason VARCHAR(32) NULL COMMENT '结束原因';
```

---

### 1.2 状态枚举标准化

```text
WAITING_STREAM     // 已返回推流地址，等待前端推流
STREAM_ARRIVED     // ZLM 流已到达
INVITING           // SIP INVITE 已发出
CONNECTED          // 收到 200 OK
FAILED             // 失败（超时 / 错误）
ENDED              // 正常结束
```

⚠️ 禁止出现“临时字符串状态”

---

## 二、状态机约束（CC 必须遵守）

### 2.1 合法状态流转表

```text
WAITING_STREAM
  -> STREAM_ARRIVED
  -> FAILED (timeout)

STREAM_ARRIVED
  -> INVITING
  -> FAILED (media error)

INVITING
  -> CONNECTED
  -> FAILED (sip timeout)

CONNECTED
  -> ENDED (BYE / stream_departure)

FAILED
  -> ENDED (资源回收完成)
```

---

### 2.2 所有状态更新必须满足 CAS 条件

**示例（DAO 层）**

```sql
UPDATE voice_session
SET status = :newStatus,
    version = version + 1
WHERE id = :id
AND status = :expectedStatus;
```

> ❌ 禁止：直接 update 不判断当前状态

---

## 三、prepareTalk 优化（入口安全）

### 3.1 明确设置超时时间

```php
$expiresAt = date('Y-m-d H:i:s', time() + 15);
```

```php
'status' => WAITING_STREAM,
'expires_at' => $expiresAt,
'version' => 0,
```

---

### 3.2 SSRC 分配策略（不变，但必须兜底）

* prepareTalk 分配 SSRC
* FAILED / ENDED 必须释放
* 释放逻辑必须幂等

---

## 四、handleStreamArrival 优化（关键路径）

### 4.1 状态推进必须 CAS

```php
$updated = $dao->updateStatusIf(
    $sessionId,
    WAITING_STREAM,
    STREAM_ARRIVED
);

if (!$updated) {
    // 已被超时 / 已结束
    return;
}
```

---

### 4.2 startSendRtpPassive 失败处理

```php
if ($openResult['code'] != 0) {
    markFailed($session, 'rtp_open_failed');
    return;
}
```

`markFailed()` 只做：

* 更新状态 FAILED
* 记录 ended_reason
* **不释放资源**

---

## 五、SIP 回调处理（200 OK）

### 5.1 onSipResponseOk 必须校验状态

```php
if ($session['status'] !== INVITING) {
    return; // 已超时 / 已结束
}
```

### 5.2 状态推进

```php
updateStatusIf(INVITING, CONNECTED);
```

---

## 六、超时处理设计（重点：不要学 Java）

### 6.1 定时扫描（Cron / Redis / Queue 均可）

**每 5 秒执行一次**

```sql
SELECT id
FROM gv_voice_sessions
WHERE status IN (WAITING_STREAM, INVITING)
AND expires_at < NOW()
LIMIT 100;
```

---

### 6.2 超时处理逻辑（只改状态）

```php
updateStatusIf(
  current_status IN (WAITING_STREAM, INVITING),
  FAILED,
  ended_reason = 'timeout'
);
```

❌ 禁止在这里：

* 发送 BYE
* 释放 SSRC
* 操作 ZLM

---

## 七、资源回收统一出口（最重要）

### 7.1 stopVoiceTalkBySession 是**唯一资源释放点**

它必须满足：

* 可重复调用
* 状态已 ENDED 直接 return
* 所有外部调用都走这里

---

### 7.2 标准释放顺序（CC 固定模板）

```text
1. CAS: status != ENDED → ENDED
2. 发送 BYE（如果 dialog_id 存在）
3. 停止 RTP / ZLM
4. 释放 SSRC
5. 删除 sendRtpInfo
6. 记录 ended_at / ended_reason
```

---

## 八、流离开事件（on_stream_changed regist=false）

### 8.1 只做一件事

```php
stopVoiceTalkBySession($session);
```

> ❌ 禁止在 hook 里直接释放 SSRC

---

## 九、幂等与防并发清单（CC 自检表）

在写代码时，必须检查：

* [ ] stopVoiceTalk 可重复调用？
* [ ] FAILED → ENDED 是否只执行一次？
* [ ] SSRC 是否可能被释放两次？
* [ ] 状态更新是否依赖当前状态？
* [ ] 超时逻辑是否“无副作用”？

---

## 十、禁止事项（红线）

🚫 禁止引入：

* 类似 Java DynamicTask 的 `delay → 强制 stop`
* 内存变量判断会话状态
* 不带条件的 UPDATE
* 在定时器中直接发 BYE
