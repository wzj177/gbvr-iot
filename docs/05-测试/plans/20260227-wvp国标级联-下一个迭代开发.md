## 15. 级联上级平台（WVP 作为客户端）

本章描述 WVP 作为客户端向上级平台注册、维护心跳、响应上级查询、处理上级点播的完整逻辑。所有协议均遵循 GB/T 28181，实现细节来自 `SIPCommanderForPlatform`、`PlatformServiceImpl`、`InviteRequestProcessor`。

### 15.2 注册状态机

```
【配置添加 / enable=true】
      │
      ▼
  发送 REGISTER（Expires = config.expires，无认证头）
      │
      ├─ 200 OK ──────────────────────────────────────┐
      │                                               │
      └─ 401 Unauthorized                             │
           │                                          │
           ├─ 解析 WWW-Authenticate 取 realm/nonce    │
           └─ 重发 REGISTER（带 Authorization 摘要）   │
                 │                                    │
                 └─ 200 OK ──────────────────────────►├── online()
                                                      │     │
                                              ┌───────┘     │
                                              │             ▼
                                        status=true   启动 RegisterTask（expires-30s 后续注册）
                                                      启动 KeepaliveTask（每 keepTimeout 秒心跳）
                                                      若 autoPushChannel=true → 创建模拟订阅

【心跳 keepalive】──────────────────────────────────────────
  每 keepTimeout 发 MESSAGE（XML Keepalive）
    ├─ 200 OK → 失败计数清0
    └─ 超时/失败 → 失败计数+1
          └─ 失败计数 >= 3 → offline()

【注册到期续注册 registerExpire】
  到期前 30s → 重发 REGISTER（流程同上）

【offline()】
  status=false → 取消 RegisterTask + KeepaliveTask → stopAllPush()

【定时兜底检测（每20s）】
  查找 enable=true 但 status=false 的平台 → 触发 sendRegister

【update()】
  发 REGISTER（Expires=0）注销旧配置 → 状态丢失检测触发重注册

【delete()】
  发 REGISTER（Expires=0）注销 → 清除所有状态
```

### 15.3 REGISTER 消息格式

#### 首次注册（无认证）

```sip
REGISTER sip:340200000000000000@192.168.1.10:5060 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.100:5060;rport;branch=z9hG4bKXXX
From: <sip:340200000000000001@192.168.1.100:5060>;tag=YYYY
To: <sip:340200000000000000@192.168.1.10:5060>
Call-ID: ZZZZ@192.168.1.100
CSeq: 1 REGISTER
Contact: <sip:340200000000000001@192.168.1.100:5060>
Max-Forwards: 70
Expires: 3600
Content-Length: 0
```

> - **Request-URI** = `sip:serverGBId@serverIp:serverPort`
> - **From** = `sip:deviceGBId@deviceIp:devicePort`（WVP 本级编号）
> - **To** = `sip:serverGBId@serverIp:serverPort`（与 Request-URI 一致）

#### 401 Digest 认证重注册

收到 401 后解析 `WWW-Authenticate` 头，计算 HA1/HA2/response：

```
HA1    = MD5(username:realm:password)
HA2    = MD5("REGISTER":uri)
response = MD5(HA1:nonce:HA2)
```

重发 REGISTER，附加 `Authorization` 头：

```sip
Authorization: Digest username="340200000000000001", realm="3402000000",
    nonce="XXXXXXXX", uri="sip:340200000000000000@192.168.1.10:5060",
    response="YYYYYYYY", algorithm=MD5
```

#### 注销（Expires=0）

```sip
REGISTER sip:serverGBId@serverIp:serverPort SIP/2.0
...
Expires: 0
```

### 15.4 心跳消息格式

WVP 向上级发 `MESSAGE` 请求，Body 为：

```xml
<?xml version="1.0" encoding="GB2312"?>
<Notify>
  <CmdType>Keepalive</CmdType>
  <SN>12345</SN>
  <DeviceID>340200000000000001</DeviceID>
  <Status>OK</Status>
  <Info/>
</Notify>
```

> - `DeviceID` = 本级 `deviceGBId`
> - `SN` = 随机序列号（每次递增或随机）
> - `Status` 固定为 `OK`
> - 上级回 200 OK 即心跳成功；连续 3 次无响应则判定下线

### 15.7 上级发起点播（处理 INVITE）

#### 总体流程

```
上级发 INVITE（SDP含SSRC）
  │
  ├─ 解析 From 头取 requesterId
  ├─ 按 requesterId 查找 Platform 配置
  ├─ 检查目标 channelId 是否在本平台共享列表（wvp_platform_channel）
  │       └─ 不在 → 回 404 Not Found
  │
  ├─ 回 100 Trying
  │
  ├─ 解析请求 SDP（s=Play/Playback/Download）
  │
  ├─ channelPlayService.startInvite()
  │       └─ 若实时流：触发下级设备点播 / 接流
  │       └─ 若回放：触发历史录像检索
  │
  ├─ 构建 SendRtpInfo（目标IP:port, SSRC, 流标识, TCP/UDP, 主被动）
  ├─ sendRtpServerService.createSendRtpInfo() → 存入 Redis
  │
  ├─ 构建 200 OK SDP（WVP发流地址）
  ├─ 等待 ACK（超时60s）
  │
  └─ 收到 ACK → ZLM 开始推流（RTP发给上级IP:port）
```

#### 请求 SDP 解析规则

| `s=` 字段 | 类型 | 附加解析 |
|-----------|------|---------|
| `s=Play` | 实时点播 | 无 |
| `s=Playback` | 录像回放 | `u=` 行第一段取 channelId，`t=` 行取开始/结束时间（NTP-unix offset=2208988800） |
| `s=Download` | 录像下载 | 同上 + `a=downloadspeed:X` 取下载倍速 |

```
解析传输方式：
  m= 行 protocol 字段：
    RTP/AVP → UDP
    TCP/RTP/AVP → TCP
  若 TCP：
    a=setup:active  → 上级主动连 WVP（WVP被动监听）
    a=setup:passive → WVP主动连上级
```

#### 200 OK SDP 格式（WVP 发给上级）

```sdp
v=0
o=- 0 0 IN IP4 192.168.1.100
s=Play
c=IN IP4 192.168.1.100
t=0 0
m=video 30000 RTP/AVP 96
a=rtpmap:96 PS/90000
a=sendonly
y=0200000001
```

> - `c=` 使用 `sendStreamIp`（若配置）或 ZLM 的 `sdpIp`
> - `m=` 端口由 ZLM 分配（`createSendRtpInfo` 返回）
> - `y=` 为 SSRC，优先使用上级 SDP 中携带的值
> - 回放/下载时 `s=Playback` / `s=Download`
> - TCP被动时 `m=` 行改为 `TCP/RTP/AVP` 并加 `a=setup:passive`

#### BYE 处理

上级发 BYE 时：
1. WVP 回 200 OK
2. 停止对应 ZLM 推流任务（`sendRtpServerService.stopSendRtp()`）
3. 若为点播：向下级发 BYE 停止拉流

WVP 主动发 BYE 的触发条件：
- ZLM 流消失事件（`MediaDepartureEvent`）
- 推流停止事件（`MediaSendRtpStoppedEvent`）

### 15.8 语音广播（WVP 向上级发 INVITE 请求音频）

```
上级发 MESSAGE（CmdType=Broadcast）
  │
  └─ WVP 向上级发 INVITE，请求接收音频流：

INVITE sip:serverGBId@serverIp:serverPort SIP/2.0
...
Content-Type: application/sdp

v=0
o=- 0 0 IN IP4 192.168.1.100
s=Play
c=IN IP4 192.168.1.100
t=0 0
m=audio 40000 RTP/AVP 8
a=rtpmap:8 PCMA/8000
a=recvonly
y=0100000001
f=v/////a/1/8/1
```

> - `m=audio` PT=8（PCMA，G.711 A律，8kHz）
> - `a=recvonly`：WVP 接收上级推送的音频
> - `f=` 行：视频参数为空，音频 `1/8/1`（1路/8kHz/单声道）
> - 收到上级 200 OK 后，提取上级音频接收端口，WVP 开始接收 RTP 音频
> - WVP 再将音频转发给目标下级设备

### 15.9 推流状态持久化

WVP 将推流状态存入 Redis（key 前缀 `wvp_send_rtp_*`）：

**SendRtpInfo 关键字段：**

| 字段 | 说明 |
|------|------|
| `platformId` | 上级平台 serverGBId |
| `channelId` | 通道国标ID |
| `mediaServerId` | 流媒体服务器ID |
| `ssrc` | 推流 SSRC |
| `targetIp` / `targetPort` | 上级接收地址 |
| `localPort` | WVP 本地发流端口 |
| `tcpActive` | TCP 主动/被动模式 |

**重启恢复逻辑（`PlatformServiceImpl.run()`）：**

1. 启动时查询 Redis 中所有 `wvp_send_rtp_*` key
2. 均设为停止状态（防止僵尸推流占用端口）

### 15.10 集群 Failover（多节点场景）

WVP 支持集群部署，每个节点有唯一 `serverId`：

```
每 2s 执行 execute()：
  1. 读取所有在线 WVP 节点列表
  2. 检测其中是否有节点心跳超时（离线）
  3. 若离线节点负责的平台未被其他节点接管：
       server_id = 本节点 → 触发注册维护
```

平台记录的 `server_id` 字段标识当前负责注册维护的 WVP 节点。节点离线后，其他存活节点在下一个检测周期接管。

### 15.12 关键实现要点

1. **注册域（realm）来源**：`serverGBDomain` 取 `serverGBId` 前6位（WVP 构造 SIP URI 时使用）

2. **目录分批控制**：`catalogGroup` 控制每包条数（1/2/4/8），等上级回 200 OK 再发下一批，防止上级因处理过慢丢包；降级时以 30ms 间隔无等待发送

3. **心跳失败判定**：连续失败 **3次** 才判断下线，避免网络抖动误判

4. **自动推通道（autoPushChannel）**：在内存中创建 `SubscribeInfo.buildSimulated()` 模拟订阅对象，使通道变化时自动触发 NOTIFY，无需上级主动 SUBSCRIBE

5. **SSRC 选取优先级**：优先使用上级 INVITE SDP 中携带的 `y=` SSRC；若无则 WVP 自行生成（格式见第 13 章）

6. **SDP IP 选取优先级**：`sendStreamIp`（平台专属配置）> ZLM 的 `sdpIp`（全局配置）

7. **TCP 推流模式**：
    - `setup:active`（上级主动）→ WVP `a=setup:passive` → ZLM 被动监听
    - `setup:passive`（WVP主动）→ WVP `a=setup:active` → ZLM主动连接上级

8. **通道共享验证**：上级点播时，WVP 先查 `wvp_platform_channel` 确认通道在平台共享列表中，否则返回 404（防止未授权访问）
