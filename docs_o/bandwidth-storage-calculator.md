# GB28181 视频监控系统 - 带宽与存储计算方案

## 一、系统架构说明

本系统采用**分离式部署架构**，将国标信令服务器与流媒体服务器独立部署：

```
┌─────────────────┐         ┌─────────────────┐
│  GB28181 SIP    │         │  流媒体服务器    │
│  信令服务器      │────────▶│  (ZLMediaKit)   │
│                 │         │                 │
└─────────────────┘         └─────────────────┘
        │                           │
        │                           │
    管理设备                      视频流分发
    (10000+ 设备)               (带宽主要消耗)
```

### 部署建议

| 组件 | 资源瓶颈 | 建议配置 | 承载能力 |
|------|---------|---------|---------|
| **SIP 信令服务器** | 内存、网络连接数 | 4核8G，千兆网卡 | 10000+ 设备 |
| **流媒体服务器** | 带宽、CPU（转码） | 8核16G，万兆网卡 | 取决于带宽 |

## 二、带宽计算

### 2.1 计算公式

```
总带宽 = 设备数量 × 单路码率 × 并发观看系数
```

**并发观看系数**：同一时间有多少人观看视频
- 实时监控场景：0.1 - 0.3（10%-30%的设备同时被观看）
- 应急指挥场景：0.5 - 0.8
- 回放场景：按实际并发数计算

### 2.2 常见分辨率码率参考

| 分辨率 | 帧率 | H.264 编码 | H.265 编码 | 节省带宽 |
|--------|------|-----------|-----------|---------|
| **4K** (3840×2160) | 30fps | 12 Mbps | 6 Mbps | 50% |
| **4K** (3840×2160) | 60fps | 16 Mbps | 8 Mbps | 50% |
| **1080P** (1920×1080) | 25fps | 4 Mbps | 2 Mbps | 50% |
| **1080P** (1920×1080) | 30fps | 5 Mbps | 2.5 Mbps | 50% |
| **720P** (1280×720) | 25fps | 2 Mbps | 1 Mbps | 50% |
| **D1** (720×576) | 25fps | 1.5 Mbps | 0.75 Mbps | 50% |

> 注：实际码率会根据场景复杂度、运动程度、编码参数等因素浮动 ±30%

### 2.3 典型场景带宽需求

#### 场景1：32路 4K H.265 监控

```
设备数量：32台
分辨率：4K @ 30fps
编码：H.265 (6 Mbps/路)
并发系数：0.25 (8路同时观看)

总带宽 = 32 × 6 Mbps × 0.25 = 48 Mbps ≈ 6 MB/s
```

**推荐配置**：千兆网络（1000 Mbps），上行带宽充足

---

#### 场景2：100路 1080P H.264 监控

```
设备数量：100台
分辨率：1080P @ 25fps
编码：H.264 (4 Mbps/路)
并发系数：0.2 (20路同时观看)

总带宽 = 100 × 4 Mbps × 0.2 = 80 Mbps ≈ 10 MB/s
```

**推荐配置**：千兆网络

---

#### 场景3：500路 720P H.265 监控

```
设备数量：500台
分辨率：720P @ 25fps
编码：H.265 (1 Mbps/路)
并发系数：0.15 (75路同时观看)

总带宽 = 500 × 1 Mbps × 0.15 = 75 Mbps ≈ 9.4 MB/s
```

**推荐配置**：千兆网络

---

#### 场景4：1000路 1080P H.265 大型项目

```
设备数量：1000台
分辨率：1080P @ 25fps
编码：H.265 (2 Mbps/路)
并发系数：0.1 (100路同时观看)

总带宽 = 1000 × 2 Mbps × 0.1 = 200 Mbps ≈ 25 MB/s
```

**推荐配置**：千兆网络或双网口聚合

## 三、存储计算

### 3.1 计算公式

```
单设备日存储 = 码率(Mbps) × 3600 × 24 ÷ 8 ÷ 1024 ÷ 1024 (GB)
总存储 = 单设备日存储 × 设备数量 × 存储天数
```

简化公式（H.264，1080P@25fps）：
```
单设备日存储 ≈ 43 GB/天 (4 Mbps)
单设备日存储 ≈ 22 GB/天 (H.265 2 Mbps)
```

### 3.2 存储需求速查表

| 分辨率 | 编码 | 码率 | 单设备/天 | 30天存储 | 90天存储 |
|--------|------|------|----------|---------|---------|
| 4K | H.264 | 12 Mbps | 129 GB | 3.9 TB | 11.6 TB |
| 4K | H.265 | 6 Mbps | 65 GB | 1.9 TB | 5.8 TB |
| 1080P | H.264 | 4 Mbps | 43 GB | 1.3 TB | 3.9 TB |
| 1080P | H.265 | 2 Mbps | 22 GB | 648 GB | 1.9 TB |
| 720P | H.264 | 2 Mbps | 22 GB | 648 GB | 1.9 TB |
| 720P | H.265 | 1 Mbps | 11 GB | 324 GB | 972 GB |

### 3.3 典型场景存储需求

#### 32路 4K H.265，存储30天

```
单设备：65 GB/天 × 30天 = 1.95 TB
总存储：1.95 TB × 32台 = 62.4 TB
```

**推荐配置**：64TB RAID6 存储阵列

---

#### 100路 1080P H.264，存储30天

```
单设备：43 GB/天 × 30天 = 1.29 TB
总存储：1.29 TB × 100台 = 129 TB
```

**推荐配置**：144TB RAID6 存储阵列（使用 12块 16TB 硬盘）

---

#### 100路 1080P H.265，存储30天

```
单设备：22 GB/天 × 30天 = 648 GB
总存储：648 GB × 100台 = 64.8 TB
```

**推荐配置**：72TB RAID6 存储阵列

## 四、存储优化方案

### 4.1 编码优化（推荐）

| 方案 | 带宽节省 | 存储节省 | 画质影响 |
|------|---------|---------|---------|
| H.264 → H.265 | 50% | 50% | 基本无差异 |
| 降低码率 20% | 20% | 20% | 轻微损失 |
| 降低帧率 30→25fps | 15% | 15% | 基本无差异 |

### 4.2 存储策略

| 策略 | 说明 | 存储节省 |
|------|------|---------|
| **移动侦测录像** | 仅画面变化时录像 | 60-80% |
| **定时录像** | 仅在指定时段录像 | 按时段比例 |
| **码率自适应** | 静态场景降低码率 | 20-30% |
| **重要事件标记** | 手动标记永久保存 | N/A |

## 六、快速计算器

### 在线计算公式

```javascript
// 带宽计算
function calcBandwidth(deviceCount, bitrateMbps, concurrentRatio) {
    return deviceCount * bitrateMbps * concurrentRatio;
}

// 存储计算
function calcStorage(deviceCount, bitrateMbps, days) {
    const dailyPerDevice = bitrateMbps * 3600 * 24 / 8 / 1024; // GB
    return dailyPerDevice * deviceCount * days; // GB
}

// 示例：100路 1080P H.265，30天存储
const bandwidth = calcBandwidth(100, 2, 0.2);  // 40 Mbps
const storage = calcStorage(100, 2, 30);      // 约 65 TB
```

## 八、注意事项

1. **带宽考虑冗余**：实际使用时建议预留 30% 冗余
2. **存储考虑冗余**：RAID6 建议至少 2 块硬盘冗余，RAID10 更好
3. **网络隔离**：建议视频流与管理网络分离（VLAN）
4. **时间同步**：所有设备需 NTP 同步，保证录像时间准确
5. **定期维护**：硬盘寿命通常 3-5 年，建议制定更换计划
